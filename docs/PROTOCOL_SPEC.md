# MCU-Boot 通信协议规范

**版本**: v1.1

> 适用芯片：STM32F407ZGT6（App @ 0x08010000）+ STM32F103C8T6（App @ 0x08006400）。
> 协议本身芯片无关，所有芯片相关参数（地址/MTU/能力位）通过 `device_info_t` 协商。

## 1. 协议概述

### 1.1 物理层

| 项目 | 值 |
|------|-----|
| 通信接口 | UART |
| 波特率 | 115200 (默认) |
| 数据位 | 8 |
| 停止位 | 1 |
| 校验位 | 无 |
| 流控制 | 无 |

### 1.2 传输模式

- **半双工**: 主机发送请求 → 从机响应 → 主机发送下一请求
- **每包必响应**: 主机必须等待从机ACK后才能发送下一包
- **超时处理**: 默认超时 1000ms

## 2. 数据包格式

### 2.1 请求包 (Request)

```
┌─────────────────────────────────────────────────────────────┐
│  Byte 0   │  Byte 1   │  Byte 2-3    │  Byte 4...(N+3)   │  Byte N+4 ~ N+5 │
├────────────┼───────────┼──────────────┼───────────────────┼─────────────────┤
│   0xAA    │  Opcode   │  Length_L/H   │   Payload [N]     │   CRC16_L/H     │
└─────────────────────────────────────────────────────────────┘
```

| 字段 | 长度 | 说明 |
|------|------|------|
| Header | 1B | 固定 `0xAA` |
| Opcode | 1B | 操作码 |
| Length | 2B | Payload长度 (低字节在前) |
| Payload | N B | 数据负载 |
| CRC16 | 2B | Header+Opcode+Length+Payload 的 CRC16 |

### 2.2 响应包 (Response)

```
┌─────────────────────────────────────────────────────────────┐
│  Byte 0   │  Byte 1   │  Byte 2   │  Byte 3-4   │  Byte 5...(M+4) │  Byte M+5 ~ M+6 │
├────────────┼───────────┼───────────┼─────────────┼─────────────────┼────────────────┤
│   0x55     │  Opcode   │  ErrCode  │  Length_L/H │   Payload [M]   │   CRC16_L/H    │
└─────────────────────────────────────────────────────────────┘
```

| 字段 | 长度 | 说明 |
|------|------|------|
| Header | 1B | 固定 `0x55` |
| Opcode | 1B | 与请求包相同 |
| ErrCode | 1B | 错误码 |
| Length | 2B | Payload长度 (低字节在前) |
| Payload | M B | 数据负载 |
| CRC16 | 2B | Header+Opcode+ErrCode+Length+Payload 的 CRC16 |

## 3. 操作码 (Opcodes)

| Opcode | 名称 | 功能 | Payload方向 |
|--------|------|------|-------------|
| `0x01` | INQUERY | 查询设备信息 | 双向 |
| `0x04` | GET_CAPS | 获取Bootloader能力 | 请求→响应 |
| `0x21` | RESET | 复位设备 | 请求→响应 |
| `0x22` | BOOT | 启动应用程序 | 请求→响应 |
| `0x81` | ERASE | 擦除Flash区域 | 请求→响应 |
| `0x82` | PROGRAM | 写入数据到Flash | 请求→响应 |
| `0x83` | VERIFY | CRC32校验 | 请求→响应 |
| `0x84` | WRITE_HEADER | 写入镜像头 | 请求→响应 |

### 3.1 INQUERY 子命令

INQUERY (0x01) 的 Payload 第一个字节为子命令：

| SubCmd | 名称 | 请求Payload | 响应Payload |
|--------|------|------------|-------------|
| `0x00` | VERSION | `[0x00]` | 版本字符串 (ASCII) |
| `0x01` | MTU | `[0x01]` | 2字节: 最大Payload (uint16_t) |

---

## 4. 错误码

| ErrCode | 名称 | 说明 |
|---------|------|------|
| `0x00` | OK | 成功 |
| `0x01` | OPCODE | 无效操作码 |
| `0x02` | OVERFLOW | 缓冲区溢出 |
| `0x03` | TIMEOUT | 接收超时 |
| `0x04` | FORMAT | 格式错误 |
| `0x05` | VERIFY | 校验失败 (CRC/签名) |
| `0x06` | PARAM | 参数错误 |
| `0x07` | SIGNATURE | 签名验证失败 |
| `0xFF` | UNKNOWN | 未知错误 |

---

## 5. 能力标志

GET_CAPS (0x04) 返回 4 字节 uint32_t 能力标志：

| Bit | Flag | 说明 |
|-----|------|------|
| 0 | SIGNED | 支持HMAC-SHA256签名 |
| 1 | ANTIROLLBACK | 支持版本防回滚 |
| 2 | CRC | 支持CRC32校验 |
| 3 | DUAL_BANK | 支持双Bank (预留) |

**示例**: `0x07` = SIGNED | ANTIROLLBACK | CRC

## 6. 命令详解

### 6.1 INQUERY (0x01)

查询设备信息。

**请求 Payload**:
```
[SubCmd: 1 byte]
```

**响应 Payload (SubCmd=0x00 DEVICE_INFO)** — **★最重要子命令**：

24 字节 packed struct（`device_info_t`），上位机首次连接时必发，用来动态获取设备的 Flash 布局：

| 偏移 | 字段 | 说明 |
|------|------|------|
| 0-2 | bl_major / bl_minor / bl_build | Bootloader 版本 |
| 3 | has_app | 0=设备无有效 App，1=有 |
| 4-6 | app_major / app_minor / app_build | App 版本（has_app=1 时有效） |
| 7-8 | mtu | 单包最大 payload 字节数（LE16） |
| 9-12 | caps | 能力位（BIT0=SIGNED, BIT1=ANTIROLLBACK, BIT2=CRC, ...） |
| **13-16** | **header_addr** | **设备的 Header 写入地址**（动态读，不写死） |
| **17-20** | **app_base** | **设备的 App 起始地址**（动态读，不写死） |
| 21-23 | reserved | 保留 |

> 💡 **设计原则**：上位机不硬编码任何芯片相关参数。F407 报 `app_base=0x08010000`，F103 报 `app_base=0x08006400`，上位机自动适配。这是分层架构"未来变化成本最低"的体现。

**响应 Payload (SubCmd=VERSION)**:
```
[VersionString: N bytes ASCII]
```

**响应 Payload (SubCmd=MTU)**:
```
[MTU_L: 1 byte] [MTU_H: 1 byte]
```

---

### 6.2 GET_CAPS (0x04)

获取Bootloader能力标志。

**请求 Payload**: 无

**响应 Payload**:
```
[Capabilities: 4 bytes uint32_t]
```

---

### 6.3 ERASE (0x81)

擦除Flash指定区域。

**请求 Payload**:
```
[Address: 4 bytes uint32_t] [Size: 4 bytes uint32_t]
```

| 字段 | 类型 | 说明 |
|------|------|------|
| Address | uint32_t | 擦除起始地址 |
| Size | uint32_t | 擦除大小 (字节) |

**响应 Payload**: 无

**注意**:
- 地址必须对齐到Flash扇区边界
- Bootloader区域 (0x08000000-0x0800BFFF) 受保护，禁止擦除

---

### 6.4 PROGRAM (0x82)

写入数据到Flash。

**请求 Payload**:
```
[Address: 4 bytes] [Size: 4 bytes] [Data: Size bytes]
```

| 字段 | 类型 | 说明 |
|------|------|------|
| Address | uint32_t | 写入起始地址 |
| Size | uint32_t | 数据长度 |
| Data | uint8_t[] | 要写入的数据 |

**响应 Payload**: 无

**约束**:
- Size 最大值 = MTU - 8
- 地址必须4字节对齐
- 写入前必须已擦除目标区域

---

### 6.5 VERIFY (0x83)

对Flash指定区域进行CRC32校验。

**请求 Payload**:
```
[Address: 4 bytes] [Size: 4 bytes] [ExpectedCRC: 4 bytes]
```

| 字段 | 类型 | 说明 |
|------|------|------|
| Address | uint32_t | 校验起始地址 |
| Size | uint32_t | 校验长度 |
| ExpectedCRC | uint32_t | 期望的CRC32值 |

**响应 Payload**: 无

**校验失败响应**: ErrCode = VERIFY (0x05)

---

### 6.6 WRITE_HEADER (0x84)

写入镜像头到Header区域。

**请求 Payload**:
```
[HeaderData: 256 bytes]
```

| 字段 | 类型 | 说明 |
|------|------|------|
| HeaderData | uint8_t[256] | 完整的256字节镜像头 |

**响应 Payload**: 无

**注意**: 此命令绕过地址安全检查，直接写入Header区域

---

### 6.7 RESET (0x21)

复位设备。

**请求 Payload**: 无

**响应 Payload**: 无

**注意**: 从机在发送响应后会延迟2ms再执行复位，确保响应发送完成

---

### 6.8 BOOT (0x22)

启动应用程序。

**请求 Payload**: 无

**响应 Payload**: 无

**注意**:
- 执行前会验证App镜像有效性
- 验证失败则停留在Bootloader模式

```c
typedef enum {
    BL_STATE_IDLE    = 0,    // 等待帧头
    BL_STATE_HEADER  = 1,    // 收到帧头 0xAA
    BL_STATE_OPCODE  = 2,    // 读取操作码
    BL_STATE_LENGTH  = 3,    // 读取长度
    BL_STATE_PAYLOAD = 4,    // 读取数据负载
    BL_STATE_CRC     = 5,    // 读取并验证CRC
} bl_state_t;
```

## 附录

### A. CRC16 计算方式

使用 **CRC16-Modbus** 算法：

```c
uint16_t crc16_modbus(const uint8_t *data, uint16_t len)
{
    uint16_t crc = 0xFFFF;
    for (uint16_t i = 0; i < len; i++) {
        crc ^= data[i];
        for (uint8_t j = 0; j < 8; j++) {
            if (crc & 0x0001) {
                crc = (crc >> 1) ^ 0xA001;
            } else {
                crc >>= 1;
            }
        }
    }
    return crc;
}
```

### B. CRC32 计算方式

使用 **CRC32-IEEE** 算法（以太网标准）：

```c
// 多项式: 0xEDB88320 (镜像)
uint32_t crc32_ieee(const uint8_t *data, uint32_t len)
{
    uint32_t crc = 0xFFFFFFFF;
    for (uint32_t i = 0; i < len; i++) {
        crc ^= data[i];
        for (uint8_t j = 0; j < 8; j++) {
            if (crc & 1) {
                crc = (crc >> 1) ^ 0xEDB88320;
            } else {
                crc >>= 1;
            }
        }
    }
    return ~crc;
}
```
